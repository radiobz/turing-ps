## 1. 项目概述

### 1.1 定位

**图灵PS（Turing PS）**：构建一个浏览器端即可完成图片编辑的在线修图工具（类 Photoshop / 稿定设计 / Canva 的轻量形态），用户无需安装软件、无需上传原图到服务器即可完成常见修图操作，支持导出为常见图片格式。

### 1.2 目标用户与核心场景

| 场景 | 用户 | 核心诉求 |
|---|---|---|
| 日常快速修图 | 普通用户 | 裁剪、调色、滤镜、加文字，秒开即用 |
| 人像美颜 | 普通用户/自媒体 | 一键美白、磨皮、瘦脸、大眼，发朋友圈/社交平台 |
| 抠图换底 | 电商运营/设计师 | 一键去背景、商品/人像抠图、证件照换底色 |
| 内容创作 | 自媒体/电商运营 | 做封面、配图、商品图，套模板出图 |
| 创意美化 | 普通用户/设计师 | 相框、插画/艺术特效、一键提亮，让照片更有氛围 |
| 打印输出 | 普通用户 | 一键打印照片/作品（本地打印机或 PDF） |
| 隐私敏感场景 | 所有用户 | 图片尽可能不离开浏览器，本地处理 |
| 进阶处理（远期） | 设计师/运营 | AI 去水印、画幅扩展 |

### 1.3 成功标准（MVP 验收）

- 浏览器打开即用，无登录、无安装；
- 支持 图片上传/拖拽/粘贴 与 PNG/JPG/WebP 导出；
- 具备 裁剪、旋转、缩放、基础滤镜、文字、图形、图层 与 撤销/重做；
- 具备 **一键美颜**（美白/磨皮/瘦脸/大眼/红润）与 **一键抠图**（去背景/换底色）；
- 美颜全流程本地处理；抠图支持自托管服务，调用时明确提示数据去向；
- 以 MIT 兼容协议开源，托管于 GitHub。

### 2.4 推荐结论

**主选：以 `vue-fabric-editor`（快图设计，MIT）为基底，二次开发为本项目编辑器内核。**

理由（决策矩阵）：

| 评估维度 | vue-fabric-editor | miniPaint | poster-design | 无界云图 |
|---|---|---|---|---|
| License 商用友好 | ✅ MIT | ✅ MIT | ❌ AGPL（v2） | ✅ MIT |
| 功能完整度 | 高（图层/滤镜/文字/模板/快捷键） | 中高（类 PS） | 最高（+PSD/AI） | 高（素材/模板） |
| 二次开发友好度 | 高（插件化、组件化、中文文档） | 中（单体 JS） | 中（结构复杂） | 中（React 系） |
| 技术生态 | Vue3 国内普及 | 原生 JS | Vue3 | React |
| 维护活跃度 | 高 | 高 | 高 | 高 |
| 社区/star | ~7.9k | ~3.5k | ~4.9k | — |

> - 若团队偏好 **React**：改用 `无界云图`（MIT）为基底，选型结论不变。
> - 若只想做 **最轻量的类 PS 工具**：可直接引用 `miniPaint`（MIT）。
> - **基底对照排除**：`tui.image-editor`（MIT，7.7k★）滤镜体系更丰富、更贴近"修图"，但**无图层、素材/相框/装饰叠加能力弱**，且原版维护放缓；`filerobot`（MIT）为 React 系、同样无图层与贴纸。本方案因"相框 + 装饰特效 + 文字特效"依赖**素材图层叠加**，仍以 vue-fabric-editor 为基底，滤镜短板由 pixels.js（MIT）补齐。
> - **不建议直接整体引用**：poster-design v2（AGPL 商用义务）、IOPaint/inpaint-web（专项 AI 工具，仅作可选增强模块引入）。
> - Photopea：核心非开源，仅社区仓库，**不可直接引用**。

## 3. 技术选型

### 3.1 技术栈（基于 vue-fabric-editor 基底的推荐组合）

| 层 | 选型 | 说明 |
|---|---|---|
| 框架 | Vue 3 + Vite + TypeScript | 基底自带，生态成熟 |
| 画布引擎 | Fabric.js | 对象模型、图层、交互事件 |
| UI 组件 | Element Plus / View UI Plus | 中文文档、表单与面板组件齐全 |
| 状态管理 | Pinia | 编辑状态、历史栈、用户设置 |
| 样式 | SCSS + CSS 变量 | 支持主题切换（明/暗） |
| 构建部署 | Vite + GitHub Pages / Vercel | 纯静态可一键部署 |

### 3.2 关键选型说明

- **为什么不从零写画布引擎**：Fabric.js 已覆盖对象拾取、变换、序列化、滤镜等核心能力，从零实现周期长且易出交互缺陷；基座项目已将其工程化封装。
- **为什么选 vue-fabric-editor 而非其他**：唯一同时满足「MIT + 功能完整 + 插件化 + 中文维护 + star 领先」的完整编辑器。
- **美颜引擎**：**直接引用现成开源算法库，不自研**——主推 `GPUPixel`（Apache-2.0，pixpark，内置磨皮/美白/瘦脸/大眼/口红，商业级效果），通过 Emscripten 编译 WASM 嵌入浏览器（一次性集成）；备选 `open-makeup-sdk`（MIT，npm 直接引入，浏览器端现成，但 v0.1.0 较新需评估）；兜底 face-api.js + 开源滤镜组装。
- **抠图方案**：默认 `rembg`（MIT）以独立 Docker 服务部署，前端上传 → 服务返回透明 PNG → 作为新图层插入画布；浏览器端方案（自研 U2Net ONNX）列为远期选项。**不引入 AGPL 的 @imgly**，避免许可证污染。
- **服务端策略**：MVP 阶段除「抠图」外**零后端**；AI 能力通过"可选独立服务"提供，核心产品不绑定。

### 4.2 用户核心路径（MVP）

```
打开页面 → 上传/拖拽图片 → 编辑（裁剪/滤镜/美颜/抠图/相框/插画特效/提亮/文字/图层）→ 撤销纠错 → 导出下载 / 一键打印
（常用操作全程本地；抠图调用自托管服务时显著提示图片上传）
```

│  │   美颜引擎（GPUPixel WASM，本地处理）               │ │
│  │   人脸检测 → 美白/磨皮/瘦脸/大眼 → 图层合成           │ │

                                              └──────────────────┘

### 5.2 前端模块划分

| 模块 | 职责 | 边界 |
|---|---|---|
| `canvas/` | Fabric.js 封装：初始化、对象管理、事件、缩放平移 | 不感知业务 |
| `tools/` | 各编辑工具（裁剪、画笔、文字、形状…） | 通过统一工具接口注册 |
| `filters/` | 滤镜预设与参数化滤镜管线 | 纯函数，可单测 |
| `effects/` | 艺术特效：插画/素描/油画/复古滤镜（pixels.js 或自研）、相框素材叠加、自动提亮 | 纯前端，可插拔 |
| `beauty/` | 美颜引擎封装：人脸检测、美白/磨皮/瘦脸/大眼/红润管线 | GPUPixel WASM，本地处理 |
| `matting/` | 抠图：调用 rembg 服务或浏览器端模型，产出透明 PNG 图层 | 独立服务适配，可插拔 |
| `history/` | 撤销/重做：操作命令记录 + 状态快照混合 | 与编辑器解耦 |
| `importer/` | 文件/URL/剪贴板解析与图像加载 | 支持 PSD 可作 P1 增强 |
| `exporter/` | 画布序列化、格式转换、下载 | 支持 JSON 工程文件 |
| `store/` | Pinia 状态：文档、选中对象、工具态、UI 态 | 单一数据源 |
| `plugins/` | 插件注册表：右键菜单、快捷键、自定义工具 | 扩展点 |
| `ui/` | 工具栏、面板、弹窗、主题 | 消费 store，不含业务逻辑 |

### 5.3 数据流

```
用户操作 → 工具模块 → Editor Core（更新 Fabric 对象 + 写入历史栈）
        → Pinia 状态同步 → UI 面板响应式刷新
撤销/重做 → 历史栈 → 恢复画布状态 → 状态同步
导出 → 序列化画布 → 本地渲染 → 下载文件
```

## 6. 核心模块设计要点

### 6.1 历史记录（撤销/重做）

- **策略**：命令模式（操作级）为主，图像级操作（滤镜重算、大规模变换）用快照；
- **容量**：默认保留最近 50 步，可配置；快照使用压缩存储避免内存暴涨；
- **边界**：跨工具统一入口（`history.push(action)`），保证撤销链连续。

### 6.2 滤镜管线

- 参数化滤镜（亮度/对比度/饱和度）采用 Fabric 内置或 WebGL 着色器；
- 预设滤镜（黑白/复古/胶片）输出为可复算参数组合，不做一次性破坏性应用；
- 支持滤镜栈：多个滤镜叠加并可独立调整/移除。

### 6.3 裁剪交互

- 裁剪框拖动 + 比例锁定（自由/1:1/4:3/16:9/平台尺寸预设）；
- 裁剪前保留原图，可二次调整；确认后非破坏性记录（保留撤销）。

### 6.4 导入导出

| 方向 | 格式 | 说明 |
|---|---|---|
| 导入 | PNG/JPG/WebP/SVG/GIF（静态帧）/PSD（P1） | 剪贴板粘贴为 P0 |
| 导出 | PNG/JPG/WebP | 含质量/尺寸选项；WebP 为 P0 默认之一 |
| 工程文件 | JSON | 保存可再编辑的工程（P1） |

### 6.5 性能预算（MVP）

- 单图 ≤ 4096×4096 可流畅编辑（Fabric 对象 + 视口缩放）；
- 大图自动降采样预览，导出时按原分辨率渲染；
- 历史快照超过阈值自动合并或降级为命令记录。

### 6.6 美颜管线（一键美白/美颜，引用现成库）

1. **算法引擎**：引入 `GPUPixel`（Apache-2.0，WASM 编译版）或 `open-makeup-sdk`（MIT），提供磨皮/美白/瘦脸/大眼/口红现成滤镜，**不自行实现算法**；
2. **人脸检测**：由引擎内置或 face-api.js（MIT）完成，浏览器本地执行；
3. **参数映射**：前端滑块（美白/磨皮/瘦脸/大眼强度 0–1）映射到引擎参数；
4. **合成**：处理结果作为一次编辑操作写入历史栈（可撤销），与画布其他图层无损合成；
5. **性能**：WASM/WebGL 加速，大图降采样预览，导出按原分辨率重算。

### 6.7 抠图（一键抠图）

- **服务端（默认）**：前端选择抠图 → 上传原图至 rembg HTTP 服务 → 返回透明 PNG → 作为新图层插入画布，可继续二次编辑/换底色；
- **隐私**：调用前显著提示"图片将上传至自托管服务"；支持无服务降级（提示不可用）；
- **浏览器端（远期）**：ONNX Runtime Web + U2Net 模型（Apache-2.0）本地推理，全流程不出浏览器；
- 抠图结果支持羽化/收缩边缘、替换纯色背景（证件照换底色）。

### 6.8 图层合成

- 所有增强（美颜、抠图、滤镜、特效、相框）统一落为画布图层，保持非破坏性编辑；
- 导出按最终画布状态输出，与所见一致。

### 6.9 特效与相框

- **相框**：相框素材以图层形式叠加（基座素材系统），支持缩放/透明度/图层顺序；程序化边框（描边/圆角/纹理）由基座边框能力提供；内置相框素材包（自绘或采用可商用开源素材，注意素材版权）；
- **文字特效**：基于基座特效字体能力（描边/阴影/渐变/填充组合），内置"艺术字"预设集（描边字/渐变字/3D 字/霓虹字等），一键套用、属性仍可继续编辑；
- **装饰特效**：贴纸/装饰元素库，仅内置**可商用授权**素材（OpenStickers 等，Craftwork License / CC0）；光效/氛围效果（辉光/星光/烟雾）以透明 PNG 素材或自研滤镜叠加；
- **插画/艺术特效**：预置 pixels.js 100+ 滤镜（复古/色调/艺术类）；素描/油画/卡通化算法按需自研（OpenCV.js 或 Canvas 算法：边缘检测 + 颜色量化 + 模糊混合）；
- **一键提亮**：自动曝光——分析直方图，自动调整亮度/对比度/色阶（自研算法，可撤销，并入滤镜管线）。

### 6.10 打印

- 打印版式：导出前可选纸张尺寸（A4/6 寸等）与布局（单张/多图）；
- 输出：使用浏览器原生 `window.print()` + 打印样式（`@media print`），无需服务端；与导出流程共用渲染管线。
